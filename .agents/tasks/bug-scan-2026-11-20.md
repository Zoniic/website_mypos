## Bugs
1. **KB article "Change paper K1" always shows 404** (th/en/zh), although the hardware/software KB pages, KB search and the sitemap link to it. The stored slug contains spaces (`"Change paper K1"`). The page `<title>` resolves the article, but the page body renders the not-found page, so the page component most likely receives the URL-encoded slug and the DB lookup misses. Confirm when fixing.
2. **No slug is URL-safe for products, accessories or KB categories.** Products: all 11 (`mypos-K1`, `mypos-FM-EA-SLIM-22-(Desktop)`, `TEST`, ...). Accessories: all 9 (`mypos-Scale ACS`, `mypos-IMO Printer`, `mypos-Pager 20 Pcs`, ...). KB category: `"Change paper"`. Slugs are case-sensitive, so `/th/products/mypos-k1` shows 404. The admin accepts any slug, so new content with spaces will break the same way as bug 1.
3. **Contact page map is blank** (th/en/zh). The map URL in Site Settings is a normal Google Maps search link (`https://www.google.com/maps?...&output=search...`); Google blocks it inside an iframe (X-Frame-Options: sameorigin). It needs an embed URL (Google Maps: Share > Embed a map, `https://www.google.com/maps/embed?pb=...`).
4. **Unknown URLs return HTTP 200 instead of 404** (soft 404). The visitor sees the correct 404 page, but search engines get 200. Affects any unknown path and unknown product / blog / reference / KB / careers / order pages. Only /solutions/* and /industries/* return a real 404 (handled in src/proxy.ts).
5. **Content:** home stats band shows the URL `https://www.fm1896p.co.th/` as the "stores using" number; the "TEST" product is live (products page, solution model tables, sitemap, contact?product=TEST).
