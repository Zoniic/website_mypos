# สรุปงานปรับปรุงหลังบ้าน (รายการ 1, 5, 6)

สถานะ: ทำในโค้ดแล้วที่ branch `admin-improve` ยังไม่ push ยังไม่ deploy ไม่มีอะไรแตะฐานข้อมูลจริง

## ทำอะไรไปแล้ว

**1. ข้อความติดต่อ / ขอใบเสนอราคา / แจ้งซ่อม**
- กรองตามสถานะ ผู้รับผิดชอบ หัวข้อ (เฉพาะข้อความติดต่อ) และช่วงวันที่ ค้นหาชื่อ เบอร์ สินค้า ข้อความ แบ่งหน้าละ 25 รายการ
- ช่องบันทึกภายในและผู้รับผิดชอบในแต่ละรายการ
- ปุ่มส่งออก CSV ตามตัวกรองที่เลือก (เปิดใน Excel ได้ ภาษาไทยไม่เพี้ยน กันสูตรแฝง) หน้าผู้รับข่าวสารใช้ตัวส่งออกเดียวกันและข้อความเป็นภาษาไทย
- ข้อจำกัด: Excel ตัดเลข 0 หน้าเบอร์โทร ต้องนำเข้าคอลัมน์เป็นข้อความ

**6 (อัปโหลดรูป) ตามที่ทำจริง**
- ตรวจชนิดไฟล์จากเนื้อไฟล์ ไม่เชื่อแค่นามสกุล ไฟล์ปลอมถูกปฏิเสธพร้อมข้อความไทยที่บอกชื่อไฟล์
- ย่อรูปไม่เกิน 2000 px แปลงเป็น WebP
- เมื่อเปลี่ยนรูปหรือลบรายการ ไฟล์เก่าถูก **ย้าย** ไปโฟลเดอร์ `_trash/` ใน bucket (กู้คืนได้ ไม่ลบจริง) และไม่ย้ายถ้ายังมีที่อื่นใช้อยู่
- สคริปต์หาไฟล์กำพร้า `prisma/find-orphan-uploads.ts` รันแบบดูผลอย่างเดียวเป็นค่าเริ่มต้น

**ค่าตอน deploy (header, แจ้งเตือน, สำรองข้อมูล)**
- ใส่ header ความปลอดภัยและ CSP แบบ report-only (ยังไม่บล็อกอะไร)
- แถบเหลืองบนทุกหน้าแอดมินเมื่อยังไม่ตั้งทั้ง LINE และอีเมล
- สคริปต์ส่งออกข้อมูล `prisma/backup-db.ts` และเอกสาร `docs/deploy-checklist-th.md`

## สิ่งที่ยังต้องให้คุณหรือโฮสต์ทำ
1. **อนุมัติ schema**: ไฟล์ `.agents/tasks/admin-improve/lead-fields.sql` เพิ่มคอลัมน์ว่างได้ (ไม่ลบข้อมูล) ต้องรันที่ฐานข้อมูลจริงก่อน มิฉะนั้นสามหน้า lead จะพังบนฐานข้อมูลจริง
2. **Header / proxy**: HSTS และ `x-forwarded-for` ตั้งที่ reverse proxy (ดู checklist ข้อ 5, 6) การเปลี่ยน CSP เป็นแบบบังคับต้องให้คุณอนุมัติหลังทดสอบด้วย Pixel ID จริง
3. **สำรองข้อมูลของโฮสต์**: ต้องเปิดดูหน้า Backups ของ Supabase เอง สคริปต์ส่งออกไม่ใช่การสำรองของโฮสต์ และยังไม่เคยทดสอบกู้คืน
4. **อนุมัติลบไฟล์กำพร้า**: รันสคริปต์ dry run กับ bucket จริง ดูรายการ แล้วค่อยอนุมัติ `--write` (ย้ายไป `_trash`) และการล้าง `_trash`
5. **รายการ 5 (ตัวจำกัดจำนวนครั้ง)**: ในโค้ดยังไม่ได้แก้ เพราะแผนตีความเลข 5 เป็นเรื่อง `x-forwarded-for` ฝั่งโฮสต์ ถ้าต้องการย้ายตัวจำกัดไปเก็บในฐานข้อมูล แจ้งได้

## ตรวจอย่างไร
ตรวจบนฐานข้อมูลทดลอง (Docker พอร์ต 5433) และเซิร์ฟเวอร์ production พอร์ต 3100 ไม่ใช่ฐานข้อมูลจริง
- `tsc`, `lint`, `build` ผ่าน
- Self-test ของ CSV, ตัวกรอง, อัปโหลด, สคริปต์ไฟล์กำพร้า, สคริปต์ส่งออก ผ่านทั้งหมด
- ล็อกอินจริงด้วย Playwright: 57 ตรวจผ่านกับข้อมูลตัวอย่าง (กรอง ค้นหา แบ่งหน้า CSV บันทึกโน้ต เปลี่ยนผู้รับผิดชอบ แถบแจ้งเตือน) และ 14 ตรวจผ่านกับข้อมูลว่าง
- อัปโหลดไฟล์ข้อความที่ตั้งชื่อ .png ถูกปฏิเสธด้วยข้อความไทย
- ดู header จริงด้วย HTTP ของ /th /en /zh และหลังบ้าน CSP แบบ report-only มา, Cache-Control เดิมไม่เปลี่ยน, เปิด 7 หน้าไม่มี violation

## ยังไม่ได้ตรวจ
- การย้ายไฟล์ใน Supabase จริง (ไม่มี key ในเครื่องทดลอง) ตรวจด้วย storage จำลองเท่านั้น
- Pixel GA/Meta/TikTok, YouTube, Google Maps โหลดจริง (เครื่องทดลองไม่มี Pixel ID และไม่มีเนื้อหาฝังเหล่านี้) ตรวจได้เพียงว่า CSP ครอบโดเมนที่โค้ดใช้
- แถบแจ้งเตือนหายไปเมื่อตั้งช่องทางแจ้งเตือนแล้ว
- ทดสอบกับฐานข้อมูลจริง และการแสดงผลบนมือถือ
